# 第 9 步证据审查工作流

业务调研和 UED 共用本流程。第 5 步用[审查清单](review-checklist.md)设计覆盖，第 8 步形成草稿和运行记录后进入 9.1。纯下载在第 4 步完成 APK 校验后交付。

## 9.1 准备证据并清点缺口

打开任务级[审查与交付记录](delivery-record.md)，执行 `begin-review` 登记本轮事实版本和适用审查面，再开始本轮核对。原始问题、范围、样本与 H5 版本、场景、流程图及证据沿用任务已有文件。

先查草稿、流程图注释、清单和运行记录中标记为未查、未测、未走通、未用模拟数据、待确认、未知或含义相近的项，再检查未标记但缺少代码或运行证据的项。按问题、路由、页面或分支 ID 登记缺口及下一项确认动作。已有完整实测时可引用证据关闭“未用模拟数据”项。其余优先补证，可并行核查独立审查项。

## 9.2 分工并收齐本轮结果

按[审查清单](review-checklist.md)分派本轮适用审查面。能隔离时每面开新审查上下文，使用 `spawn_agent` 时设 `fork_turns: "none"`。先给原始问题、范围、版本、原始证据入口和分工，让审查者独立枚举，再给草稿、已知缺口和现有清单做比对。名额不足时依次启动。无法隔离时，主 agent 在当前会话分面执行相同的枚举与比对，并记录执行方式。

每面回传关联 ID、证据位置、结论和剩余动作。主 agent 等全部适用面交回完整比对结果后执行 `finish-review`，封存本轮新产生的证据。派发、独立枚举和部分返回均属于进行中。审查者失败或结果不全时补齐该面，必要时使用当前会话复核。多个审查者并行只算一轮。分歧回查原证据，共用设备上的实测由主 agent 排队协调。

## 9.3 修正、补证或判定阻塞

按[完成条件](completion.md)分派缺口，合并同轮问题并检查[回路预算](loop-budget.md)。缺实现或入口证据回第 5–6 步，缺交互或图片回第 7–8 步，图文矛盾同步修正。必要场景在 App 宿主执行，按[运行与 Mock](runtime-and-mock.md)处理登录、会话和数据条件。回填原清单，保留旧轮次。需要外部输入或续批时按[阻塞判定](completion.md#真实阻塞与结论边界)记录并保留恢复点。

## 9.4 对当前版本重审

首审结束后至少独立再审一轮，即使首审没有发现。凡修改事实、范围、流程图语义或用于验收的证据，更新事实版本并回 9.1。复审收齐当前版本的全部适用面，逐项核对上一轮缺口、修正影响的上下游和原证据是否仍适用。补测及主 agent 修正自检作为复审输入。复审中新发现问题回 9.3，直到最后一次修正后的版本通过。

## 9.5 检查第 10 步入口

核对[完成条件](completion.md#第-9-步的完成门槛)，运行记录校验的 `review` 阶段。正式交付要求最新完整复审通过且缺口全部关闭。真实阻塞或用户要求先看时，可对已核实范围完成审查并用 `--partial` 校验，剩余缺口保持开放。校验通过后进入[报告审查](report-review-workflow.md)或 [UED 图册验收](ued-workflow.md#交付验收与进度)。
