# 海外 App 调研

动态资源和脚本执行约定见 [CLI 执行](cli.md)。下文 `scripts/`、`references/`、`examples/` 均相对于解析出的资源根；文档链接按当前文件位置解析。

支持业务调研与 UED 界面提取两个分支，共用取包、代码恢复、运行、Mock 和 [页面发现与图片提取](ui-extraction.md)。先取得正确样本，再确定页面范围、准备状态并采集原始 UI；不以截图数量或 Mock 结果代替可达性与完整性结论。对外交付按所选分支组织，代码、接口、哈希与技术复核材料在任务目录内部留档。

## 请求分支

| 用户目标 | 执行与交付 |
|---|---|
| 只下载/导出 APK | 前四步及收尾，读 [下载子工作流](download-workflow.md) |
| 业务调研：业务链路、条件、功能/字段/权限（可同时要图册） | 完整十步，读 [业务调研工作流](research-workflow.md)；交付业务流程、条件、功能描述、Mermaid 和对应 UI |
| UED：只要页面/状态截图、可浏览图册 | 完整十步，读 [UED 界面提取工作流](ued-workflow.md)；交付页面/状态目录、原始图片、可浏览图册和覆盖范围，不默认编写业务报告或 Mermaid |

按请求目标而非用户职位选分支。判断看用户要的答案：“为什么/怎么走/有哪些字段权限”选 `research`；“长什么样/有哪些页面/要图”选 `ued`；两者都要选 `research`，共用一份页面清单与图片，分别组织业务报告和图册。“整款 App”是范围，不是分支。第 5 步前两个完整分支必须读 [调研闭环与完成条件](completion.md)；第 5–9 步两个分支都必须读 [共用页面提取模块](ui-extraction.md)，按同一 H5 动态入口规则确定截图范围；该模块再调用 [截图与长图操作](screenshot-workflow.md)。

## 主工作流

执行前先读 [整体编排说明与 Mermaid 流程图](orchestration.md)，理解三个分支的判断位置、共用模块、验收和交付；再按所选分支读取对应操作文档。

两个完整分支复用以下十步，不另建一套取包或截图流程。前四步读 [下载子工作流](download-workflow.md)；渠道选择和依次尝试均属于第 3 步，不单列规划阶段。

| 阶段 | 依赖与动作 | 通过条件 |
|---|---|---|
| 1. 环境检查 | 先输出正文进度，运行 `python3 scripts/preflight.py --report <任务目录>/environment.json`；已知市场可加 `--country PH` | 返回码为 0、`status=passed`、`downstream_allowed=true` |
| 2. 目标识别与信息补齐 | 依赖 1；补齐市场、开发者、包名和版本，明确业务/UED 分支、整款/指定范围及待回答问题，歧义才问用户 | 目标、版本要求、分支及范围明确；无需用户逐项填写技术信息 |
| 3. 获取安装包 | 依赖 2；记录用户目标版本与取包 profile，先用 `attempts.py init` 建立取包账本，再按顺序执行已知渠道及每批最多 3 轮新增来源搜索，详见 [来源与脚本](download-sources.md) | 原始文件实际落盘、来源清单与请求条件已保存；profile 变化关联原尝试，沿用预算 |
| 4. 校验归档 | 依赖 3；先读 [校验与交付](verification.md)，运行 `python3 scripts/verify.py --input <样本目录> --package <包名>`；自动承接取包记录中的目标 versionCode | 版本要求、身份/签名与来源文件集检查通过；显式版本与记录冲突须失败，运行资源另核对 |
| 5. 拆包与代码恢复 | 检查全部 split，恢复各技术栈代码/资源，建立页面/入口/状态候选矩阵，追踪 H5 动态地址与路由 | 候选及路由覆盖依据可追溯；仅见壳或缺远端资源时转运行定位 |
| 6. 原包运行与入口定位 | 按设备选择规则确定运行设备，运行原包并观察启动、权限、登录、首页和实际原生/WebView 入口 | 原包基线、可达入口和真实阻塞点已记录 |
| 7. 按需 Mock 与场景准备 | 受登录、用户状态、配置/SDK 等阻塞时，在对应数据层构造最小本地场景，保留原 UI/业务判断 | 原页面可复现、数据合同与场景明确；必要场景已全部实测才可跳过 Mock |
| 8. 页面提取与场景走查 | 调用共用页面提取模块完成页面/状态采集；业务分支另走条件、字段权限、返回与续办，形成 Mermaid/功能草稿 | 页面覆盖与原始 UI 有证据；业务主张另有入口与链路证据 |
| 9. 证据审查 | 按 [审查工作流](review-workflow.md) 的 9.1–9.5 执行，具体查证要求见 [审查清单](review-checklist.md) | 适用项通过闭环门槛，发现缺口补证后从 9.1 重审 |
| 10. 报告与交付 | 第 9 步审查通过后，业务分支按 [报告审查工作流](report-review-workflow.md)、UED 分支按 [图册交付验收](ued-workflow.md#交付验收与进度) 检查成品；交付前重新打开实际文件确认 | 事实、交互、覆盖和适用的交付检查通过；实际文件与审查内容一致 |

第 5–9 步允许按所选分支的回路往返补证；不是要求静态反编译全部成功后才能看原包。进入第 5 步读 [包体与代码恢复](package-analysis.md) 和 [审查工作流](review-workflow.md)，第 6/7 步读 [运行与 Mock](runtime-and-mock.md)。第 8–10 步，业务分支读 [业务、UI 与报告](business-ui-report.md)，UED 分支读 [UED 界面提取工作流](ued-workflow.md)。

业务分支第 8 步组织大纲前必读 [报告结构与表达规范](../examples/business-results-report/README.md)，并打开 [双 App 可视示例](../examples/business-results-report/report.html)。补查结果合并到所属 App/阶段，示例业务结论不照搬。UED 图册遵循其分支交付结构。

## 执行记录与复核门槛

- 三个分支都按 [回路预算与用户确认](loop-budget.md) 计数。达到上限且还需重试时，暂停该回路，用户确认后只重开获准的一批。

- 沿用一个范围/证据/状态事实源：第 2 步明确分支和范围，第 5 步列候选，第 7 步据此构造场景，第 8 步补运行与 UI，第 9 步逐项审定。报告、页面目录和图册引用相同 ID，不维护重复漂移的页面结论。
- 两分支共用第 9 步的[审查工作流](review-workflow.md)，按对应审查面调用业务事实清单与图片验收规则。审查以原代码、当前资源和实际运行记录为依据。
- 按[执行检查点](rules.md)验收环境、样本、证据审查与交付。
- 工作流由 agent 编排，附带脚本执行明确的盘点/下载/校验/去重任务；脚本成功不自动等于后续反编译、Mock、事实复核或报告交付完成。

成功、失败或中断后均执行收尾：恢复本次临时网络、分析副本和设备变更，移除自己创建的转发/调试会话，保留原包与证据，说明未完成项。用户设备的数据处置遵循已有授权，不清理其他会话。收尾不是额外主流程阶段。

### 环境硬门槛

至少具备以下一个：**ADB 已授权且 shell 可响应的 Android 真机/模拟器**，或 **模拟器程序可用且已有配置和系统镜像完整、当前会话可写的 AVD**。未启动的完整 AVD 可通过，但只能标记“可准备启动”，不能声称已验证启动。仅有模拟器可执行程序、空 AVD 名称、未授权或离线设备均不算通过。AVD 目录不可写时 `preflight` 报 `AVD_NOT_WRITABLE`：模拟器连快照标记都写不进去，启动只会以 `A snapshot operation ... is pending` 退出，按[启动已配置的 AVD](network-and-devices.md#启动已配置的-avd)交用户在外部终端启动，不要新建 AVD 或清数据绕过。

没有满足条件的设备/AVD，或 ADB 检测本身不可用时，`preflight.py` 返回 4。立即输出正文错误及最小修复动作，**中断本次调研**，所有后续步骤跳过；不得继续镜像/API 下载、自动安装模拟器，或询问是否绕过门槛。即使本地已有 APK 也适用此流程要求。用户修复后重新从第 1 步检查。

VPN 在第 1 步盘点：客户端、代理、已知 controller、节点与出口的已知/未知状态。VPN 不作为全局硬门槛；第 3 步某条取包路径确实需要目标地区网络时，按 [网络与设备](network-and-devices.md) 请求相应授权。已有授权继续有效。

### 正文进度是必需输出

业务调研和 UED 提取均使用 `【序号/10 阶段｜状态】`，纯下载使用前四步和 `/4`。每个阶段开始、完成、等待用户、失败/跳过时，在聊天正文（工具调用前后的 commentary）输出真实动作/结果；状态采用进行中、完成、等待用户、失败、跳过。阶段内重要检测、换源、代码恢复、Mock 条件、路由覆盖与流程发现也须报告。

例如：`【3/10 获取安装包 · 搜索兜底 2/3｜进行中】本轮发现 2 个未尝试来源。`；`【7/10 按需 Mock 与场景准备｜进行中】该状态由原生 ViewModel 控制，网页接口拦截无法覆盖。`；`【8/10 页面提取与场景走查｜进行中】正在补动态 H5 项目的路由页面及原始长图。`

**脚本 stderr、工具日志、environment.json 不等于正文进度。** 工具返回后将真实结果概括到正文。长任务每 60 秒内提供有实际信息的更新；不要编造百分比、设备、节点或成功结果。失败时显示发生在哪一步、原因、后续已跳过什么；用户回复后先核实条件再继续。

本 skill 的盘点、下载和包体校验脚本使用标准库，身份/签名校验复用 SDK 的 aapt/apksigner；长图拼接脚本需要 Pillow。反编译、Node/Playwright、JDI、Blutter 或图像拼接依赖按技术路径检查，不要求每台机器预装全部工具。完整调研调用脚本时设置 `APP_RESEARCH_TOTAL_STAGES=10`；纯下载默认 `/4`。脚本优先用 `CLI run` 执行，它会自动设置进度分母；直接运行时必须在 `$RESOURCE_ROOT` 下并自行设置该变量。参数先看 `--help`。

## 核心决策

- 设备选择先遵从用户指定；未指定时，只读导出优先复用已安装目标 App 且满足版本要求的设备，运行调研默认任务专用模拟器，兼容性或真实硬件能力受限时再用真机。取包设备不自动成为运行设备；具体选择、可用性兜底与切换按 [设备选择顺序](network-and-devices.md#设备选择顺序) 执行。
- 页面图片提取共用 [页面发现与图片提取](ui-extraction.md)：先按本次任务确定项目/入口种子，检查动态来源，再定路由范围、准备状态、采集和核对覆盖。纳入的项目有后端/配置页面选择能力时提取当前快照全部路由；确认固定入口时从本次范围实际引用入口求导航闭包；未知时不能退化为“只截当前能点到的页面”。此规则同样用于业务分支，扩展图册不自动扩展业务结论。
- 已知取包子流程按顺序推进：本地归档 → 已连接设备导出 → 官方直接 APK → 模拟器 Play 安装后导出 → 匿名 Play → Aptoide API → APKPure API → APKCube → 其他相关已知镜像。成功则提前进入校验；未就绪路径记录原因后继续，用户指定的渠道优先。
- 已知渠道用尽后执行 Web Search。每轮执行“搜索 → 排除已尝试来源 → 尝试相关新增候选”。每批最多 3 轮，成功提前结束，无新增候选也算一轮。
- 从首次取包尝试开始维护任务级 `attempts.json`。已知路径按来源/方法去重，搜索兜底按整个来源去重。已记录设备 profile 确有变化时，使用 `--parent-id`、新 `--profile` 及证据理由建立关联尝试；同 profile 不重复，历史和已用搜索轮数保留，不通过改方法名绕过去重。
- 匿名 Play 使用 Google 的 `getItems → delivery → 安装文件`，优先复用已注册 profile/device ID；未指定版本时由脚本查询 versionCode。账号接口 `/details` 的 401、Aurora dispenser 的错误以及个人 Play 的地区限制，均不能代替匿名链路的实际结果。
- 审计全部已知路径，区分实际失败、等待输入和依赖缺失。搜索额度仅限制新来源发现，已知路径按技术卡点预算继续有据纠错。续开搜索时保留原尝试记录。
- 匿名 Google Play **不必然需要 VPN**。先查连接错误与应用地区限制；只有当前网络无法满足条件时才提出切换。IP、Play 账号地区、设备属性和应用发行范围分别判断。
- 业务调研/UED 提取默认连续执行任务专用环境内的必要操作：安装/启动、首次隐私同意与一般服务说明、用途告知、测试权限正反分支、调试副本、隔离 Mock、截图和复核，不逐按钮请求确认。已有明确授权持续有效；仅下载请求不包含运行分析。真实账号凭据、短信验证码、人机验证等无法自主取得的输入集中在实际阻塞时提出，等待期间继续独立工作。真实生产借款、还款、个人身份/生物资料提交和金融签约不因“分析/截图”而执行，改用隔离场景；若更高优先级规则明确要求交互，说明确切动作和依据。
- 用户请求“下载”不等于允许修改个人真机的应用、账号地区、系统代理或全局 VPN；已连接且已授权设备的只读 APK 导出不重复询问。
- 不把镜像页面、版本记录、PC 模拟器安装器或 Google Play 跳转链接当成 APK。保持原始字节，不合包、不重签名，不混用不同版本/渠道的分包。
- 只有旧版可得时可先下载并准确标注版本；旧版不满足“最新版”要求，不能据此结束任务。涉及付费、账号购买或真实交易合同变更时交用户决定；任务专用环境的例行说明按连续调研授权处理。
- Mock 应改数据输入而非重绘 UI/强改业务判断。H5、Android 原生、RN/Hermes、Flutter 分别选择正确的数据层；直接注入终态不证明上游自然路径。
- 原 App、原 H5 浏览器运行、组件预览与示意图分开标识。可滚动页面/弹层必须采集完整长图，单屏页面保留未经裁切的原始截图；按 [截图与长图操作](screenshot-workflow.md) 采集、拼接和校验，始终保留原帧与来源。拼接失败须说明具体原因并保留原帧，标记长图未完成，不能以多张原帧或自行补画冒充完整长图。
- 业务分支分别分析入口、条件、步骤/配置变体、字段权限、成功失败/返回/续办；专门功能调研不扩写无关主流程。UED 分支以页面/可见状态覆盖为主。两分支都结合用户状态、页面选择和按钮行为判断真实可达性，不能由页面可直接打开推断正式入口存在。
- 实际加载代码、原生导航和运行记录交叉核对；Mock 审核/支付成功、SDK 回调、静态组件存在分别不能证明真实后台成功、外部 SDK 完成或当前用户可达。
- 业务报告必须展示 Mermaid 流程图，复核范围内入口、条件分流、成功/失败、取消返回、重试和续办。总览配必要子图，不能以一张主线图或渲染通过代替业务复核。UED 图册不强制附业务流程图。

## 模块资源

- `scripts/preflight.py`：带设备硬门槛的只读环境检查；可写 environment.json 并读取已知本地 Clash/Mihomo 节点，不切换节点。
- `scripts/download.py`：APKPure、Aptoide、匿名 Play getItems/delivery、已取得直链的下载；流式写入、来源校验、分包保存。
- `scripts/export_device.py`：指定设备与包名，执行 `pm path` 和 `adb pull`，导出全部已安装 APK。
- `scripts/verify.py`：承接取包记录的目标版本，检查 CRC、身份/分包和签名；显式目标冲突即失败，详见 [校验规则](verification.md)。
- `scripts/apk_utils.py`：上述脚本共用的传输、归档和工具定位实现。
- `scripts/progress.py`：CLI 阶段进度；agent 仍须将关键进度发到聊天正文。
- `scripts/attempts.py`：任务级尝试记录、来源去重和每批 3 轮搜索额度，支持记录用户确认后的续开。搜索与浏览器操作由 agent 执行。
- `scripts/inspect_package.py`：分包载荷盘点与副本条目比对；Manifest 改变返回 `requires_manifest_review`，须语义核对后才能认定副本一致。
- `scripts/long_screenshot.py`：原帧匹配、固定栏去重、裁切拼接及像素复核；每次复核均更新最新结果和哈希，历史另存。页面完整性仍须顶部/底部与滚动容器证据。

当前 workflow 包含从取包到业务/UI 报告的完整节点。运行时恢复、Mock 合同、具体页面操作与截图参数按当前 App 证据实施，不能把历史硬编码脚本当一键通用能力。
