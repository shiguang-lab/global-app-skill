# 第 10 步业务报告审查工作流

第 9 步校验通过后，从审定的业务事实、Mermaid 源码和图片清单生成实际交付文件。10.1–10.4 每一步都从磁盘重新打开当前文件，不得依据上下文或上一轮结论；将检查结果关联到最终文件和当前内容。阶段性报告也按同一流程验收其已核实内容。纯 UED 按[图册交付验收](ued-workflow.md#交付验收与进度)执行。

## 10.1 格式与规范

- 核对用户指定的交付格式和组织要求，打开实际文件，检查标题层级、正文、列表、表格、图片说明与术语格式一致。版本和适用条件放在需要它们的地方。
- Markdown 使用 Mermaid 代码块；HTML 内嵌由 Mermaid 实际渲染的 SVG。可编辑源码保留在内部目录。离线或单文件交付按要求打包实际依赖和附件，运行检查留到 10.4。
- 按[面向读者的内容](../examples/business-results-report/README.md#面向读者的内容)核对交付边界，清理正文、附录、折叠区和 HTML 中仅用 CSS 隐藏的内部材料。用户要求技术证据时按约定范围提供。

## 10.2 结构与阅读顺序

- 从实际报告提取标题树或 DOM 章节树，按用户指定结构或[默认总分结构](../examples/business-results-report/README.md#必需的总分结构)核对。默认顺序为总览 → 各 App 独立章节 → App 内概述、主流程与阶段 → 分支、字段权限与对应原始 UI。
- 逐 App 检查流程是否连续，阶段顺序是否正确，子图、页面和状态是否归属对应阶段。补查结论回填所属 App 和阶段。导航与锚点应指向本 App 的正确层级。
- 保存实际章节树和[结构检查](../examples/business-results-report/README.md#结构检查)结果。先修正层级和归属，再审正文。

## 10.3 结论与正文

1. **先读结论。** 单独读总览、App 概述、阶段摘要和对照表的首句，确认读者能直接得到所问行为、触发方式或结果。对照表每行比较同一问题。按[结论表达规范](../examples/business-results-report/README.md#结论表达规范)补齐必要的对象、条件、动作和去向。
2. **逐段精简。** 一句表达一个判断，优先写可观察的业务动作。删掉铺垫、重复摘要、内部实现过程、空泛修饰和对已确认不存在的功能或内容的否定性罗列。把“进行相应处理”“完成后恢复”改成具体动作和结果，例如“授权成功后继续提交银行资料”。实际存在且影响用户的失败、拒绝、取消、重试和配置分流要写清结果。
3. **逐项对照第 9 步。** 核对图、正文、字段权限、图片来源、版本与适用条件，保留必要限定。清理“可能、待确认、未验证”等取证表述。范围内结论仍不确定时回第 9 步补证，删掉句子或改成肯定语气都不能关闭该问题。真实阻塞或阶段性交付按[完成条件](completion.md#真实阻塞与结论边界)处理。

## 10.4 最终 UI 与可用性

10.4 通过只说明成品可用，不是完成信号；交付前还要重新读取实际文件并确认审查覆盖当前内容（见文末）。

- 在桌面和手机尺寸实际打开修订后的交付文件。检查排版、流程图文字和分支可读性、缩放或原尺寸查看、折叠展开、导航、返回和锚点。实际点击流程图节点，确认展开并定位到所属说明或页面。检查溢出、缺图、渲染错误和 JavaScript 错误。
- 核对页面、状态和图 ID 唯一，本地文件和锚点可访问。确认图片实际加载且尺寸有效，原图可查看，长图可读，截图 SHA-256 与审定清单一致。
- 离线或单文件报告复制到空目录后断网打开，检查图、图片、导航和随附文件。记录最终打开的文件及验证结果。

## 修改、重审与交付

| 发现的问题或改动 | 重审起点 |
|---|---|
| 格式、模板、交付类型或文件封装 | 回 10.1，按顺序复查后续环节 |
| 章节、顺序、层级或内容归属 | 回 10.2，复查受影响的正文和 UI |
| 只改措辞且事实含义一致 | 回 10.3，重新打开成品执行 10.4 |
| 只改样式、布局、资源加载或坏链接 | 回 10.4；牵涉章节归属或文件封装时回对应的更早环节 |
| 事实证据不足，或改变业务条件、结果、流程连线、页面状态或范围 | 回 9.1 重新审查，审定后重新生成报告，从 10.1 开始 |

同一轮有多类改动时先合并，按[回路预算](loop-budget.md)记录返工，从最早受影响的环节重审。审查后再修改报告、图册或验收证据，必须重新读取同一文件并回 9.1 新开两轮，不能只重跑 10.4。各环节通过后，重新打开实际文件确认审查覆盖当前内容，再交付。
