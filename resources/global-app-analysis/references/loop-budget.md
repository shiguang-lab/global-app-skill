# 回路预算与用户确认

预算限制重复尝试和整轮返工。按已定范围首次处理不同的来源、页面、路由或场景，以及第 9 步正常首审和无缺口时的例行复审，沿清单推进。用稳定 ID 去重；同一根因影响多个页面时合并为一个卡点。

| 回路 | 每批自主上限 | 计数口径 |
|---|---|---|
| 第 3–4 步搜索新取包来源 | 3 轮 | 按取包记录领取轮次，无新增候选也计一轮。校验失败、换设备 profile 或换目录沿用原记录。 |
| 同一技术卡点 | 首次诊断后最多 2 次修正重试 | 每次按一个新证据或可区分的假设做修正并验证，开始时记一次。适用于已知取包路径纠错、设备/调试副本、代码/H5 资源恢复、Mock、重拍及长图拼接。同一根因换工具、页面或步骤仍累计。无新依据时提前停。脚本自身的传输、刷新和轮询上限照常执行。 |
| 第 9 步补证和重审，包括第 10 步退回的事实问题 | 3 轮返工 | 每次汇总一批缺口，启动修正并回 9.1，记一轮。第 5–8 步补证、子 agent 分工及第 10 步退回共用同一证据返工计数；一轮内可修多个缺口。 |
| 第 10 步报告或图册成品修改与重审 | 每份交付物 3 轮返工 | 同一版本发现的问题合并修改，从最早受影响的环节重审，启动时记一轮。换章节、改名、重新渲染或换审查者仍累计。回第 9 步补证计入证据返工；审定后重新生成并初检成品不额外计为成品返工。 |

同一次返工涉及技术重试时，分别检查整轮额度与卡点额度。把回路、卡点或交付物 ID、批次、已用次数、最后证据和下一动作写进原任务记录；取包搜索以 `attempts.json` 为准。跨步骤、跨会话、换审查者时沿用记录。合并重复问题、分配新子 agent 或发现少量新证据不会重置原回路额度。

## 达到上限后怎么继续

1. 完成已领取的本轮验证。仍有缺口且下一轮会超限时，暂停该回路及依赖它的交付，状态记为「等待用户决策」。独立节点可继续；没有独立工作时保存检查点并等待回复。暂停期间停止该回路的工具调用、轮询和子 agent 派发。额度用完且当前轮已通过时照常推进。
2. 合并当前需要用户决定的问题。说明哪个回路已用多少轮、已验证的结果、仍缺的证据，以及下一批要尝试的具体方法。让用户选择继续一批、提供输入或调整范围、先看已核实部分、停止。没有新的可验证方法时，优先请求具体输入或方向。
3. 用户明确同意继续后，为**获准的回路**开启一批，将该批已用计数置零。保留此前批次、失败记录、已验证事实、去重集合和其他回路的计数；如果下一动作同时受两个已耗尽额度约束，需在同一次确认中列明两个回路。用户补充的素材可直接核验。仍需重试已耗尽的回路时，等待对应的明确确认。
4. 每次新批次再次耗尽且仍有问题，重新暂停并询问；上一次继续的同意只覆盖一批。用户调整范围时更新原范围与受影响的验收项；用户要求先看结果时按[完成条件](completion.md#真实阻塞与结论边界)验收已核实部分。等待用户决策不会把缺口标记为完成。
