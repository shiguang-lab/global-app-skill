# 共用页面发现与图片提取

业务调研和 UED 分支在第 5–9 步共同使用本模块：**发现页面 → 判断动态入口与覆盖范围 → 准备原实现状态 → 截图/长图 → 覆盖复核**。截图命令、长图拼接和像素校验统一调用 [截图与长图操作](screenshot-workflow.md)，不在各分支另写一套。

输入为已校验的 App/分包、当前任务范围、恢复资源与实际运行记录。输出为同一份页面/状态清单、入口与 H5 覆盖依据、原始图片及缺口。模块规定分析与提取方法，不声称单个脚本能自动枚举任意加固 App 或全部远端页面。

## 1. 建立页面候选与唯一事实源

沿用任务已有候选/证据矩阵并扩展页面字段；没有时在任务目录建立 `ui/pages.json`。图册、业务报告和覆盖统计从此引用稳定 `page_id`、`state_id`，不分别维护重复页面结论。

| 记录 | 必需内容 |
|---|---|
| 身份 | App 包名/版本/原包哈希；页面技术栈、宿主；H5/动态 bundle 的项目、资源版本/哈希及采集时间 |
| 定位 | Activity/Fragment/导航目标、RN screen、Flutter 路由/Widget 入口、H5 路由模板/文档及来源代码/资源/运行证据 |
| 入口 | 自然入口及上游；固定/后端下发/配置下发/未知；数据来源→转换/校验→导航消费点的证据 |
| 范围 | 请求/范围 ID、各分支分别纳入/排除与理由；H5 的全部路由/使用闭包/未知策略及依据；App 是否已证实引用该页面 |
| 状态 | 所需参数、用户/订单/权限/配置、可见变体与 fixture；自然进入/直接定位/本地 Mock 的实际进入方式 |
| 提取 | 未尝试、已采集、阻塞或待确认；截图真实来源、设备/viewport、原帧、长图/单屏、哈希、拼接与完整性复核 |
| 缺口 | 未恢复代码/懒加载资源、未知路由、打不开的页面、缺少数据/Bridge/设备能力、拼接失败及已尝试动作 |

页面身份不能只用 Activity、URL、截图哈希或组件名：同一 Activity 可含多个页面；同一路由可有不同可见状态；不同 URL 参数可能只改变数据。动态 ID 按路由模板和影响布局/交互的状态取代表值，不穷举无限业务记录；参数改变页面类型或关键布局时拆为不同状态。截图相同不能合并来源/条件不同的页面证据。

同一清单可服务多个范围：页面身份、来源图片及复核证据复用，各请求的纳入关系和完成结论分别记录。不能因为业务分支排除某页就删除 UED 所需候选，也不能因为 UED 已有该页图片就认定业务入口已验证。复用图片前核对资源版本、可见状态、设备/viewport 与当前请求一致；变化时新增采集记录，保留原证据。

## 2. 按技术栈发现和提取

混合 App 分别处理各层，同一 App 可同时有四种技术栈。静态候选先登记，再用运行宿主与实际资源交叉核对；不能只遍历首页按钮，也不能把全部字符串/资源名直接算成页面。

| 技术栈 | 页面发现 | 原始界面提取 |
|---|---|---|
| Android 原生（含 Compose） | Manifest 组件、导航图、Activity/Fragment 启动与切换、Compose 导航/页面状态、Deep Link、菜单/按钮、Dialog/BottomSheet/SDK 入口；核对全部相关 split 和按需模块 | 在原 Activity/视图/Compose 页面运行，用自然导航定位；受状态阻塞时按原 ViewModel/Repository/数据入口准备 fixture。UI hierarchy 仅辅助定位，最终图片取前台屏幕；布局 XML/Compose 预览不能算 App 页面实拍 |
| React Native | 当前 JS/Hermes bundle 和实际加载的动态/热更新包；screen 注册、嵌套 navigator、条件注册、linking、原生导航模块和状态控制弹层。Hermes 按真实字节码/运行时能力恢复 | 在原 RN 宿主运行原组件，通过导航参数、Store/服务响应准备状态，等待 RN UI 队列与布局稳定后截屏。原生模块或内嵌 H5 继续转对应层；用网页重写组件、只找到 screen 名称都不算完成 |
| Flutter | 对应版本的 assets、libapp.so/AOT、路由表、路由生成/Router 配置、实际导航调用、条件 Widget 与平台通道；不是所有页面都有命名路由 | 在原 Flutter 引擎/宿主运行，通过原路由及数据/平台通道准备状态，再取设备屏幕。Widget 可能不出现在 Android 层级中，空层级不代表空页面；AOT/调试不可恢复时记录缺口，不能从字符串推断出截图或重写页面 |
| H5/WebView | APK 内资源与实际远端文档、Bridge/Deep Link/原生宿主、所有关联 JS/chunk、路由注册/生成、菜单与导航调用；必须执行下一节的动态入口分析 | 优先在 App 的正确前台 WebView 中加载原文档/资源并准备原协议数据；逐路由核对 URL、宿主、visible/attached 和页面特征。浏览器运行仅作明确标识的替代来源，不能计为 App 内实拍 |

同时登记页面内弹层、空态、错误/校验、权限拒绝、加载/结果等可见状态及实际存在的配置变体；以原实现为依据，不凭想象生成设计稿。系统权限框和第三方 SDK UI 分组标为外部界面，不与 App 自有页面混算；SDK 成功回调不能代替 SDK 自身界面。

## 3. H5 动态入口与覆盖决策

### 先确定本次项目与入口种子

业务分支从本次业务范围及必要上下游实际引用的 H5 入口出发；全 App UED 从 App 所有实际引用入口出发，指定 UED 从指定范围入口出发。对关联项目检查动态地址来源，不能只查当前账户可见的入口；同项目存在其他后端/配置页面选择能力时也按动态项目处理。动态项目一旦纳入，仍按下表提取该项目全部路由，不再用业务功能范围过滤路由。

固定项目只从本次范围入口求使用闭包，不额外纳入 App 其他功能的无关固定入口；跨项目跳转发现新目标时，先将目标项目加入清单并重新判断其策略。发现动态入口时把原固定策略升级为全部路由并重算范围；入口性质未知时保留未知，不能继续沿用较小的固定集合。

### 先查地址怎样进入页面导航

按每个 App 关联的 H5 项目分别判断，不能由一个项目的结论覆盖所有 WebView。追踪实际导航消费点（如 WebView 加载、Bridge 打开页面、前端 router/location 跳转），向上回溯 URL/path/route 的来源：

1. 原生、RN、Flutter、H5 中的固定地址/路由及其调用点、Deep Link 映射和页面内跳转。
2. 接口响应里的页面地址/路由、跳转结果、菜单/横幅/活动/公告配置、远端配置及本地缓存的下发值；字段名必须从当前代码/响应取得。
3. 拼接模板、参数替换、重定向、域名/路径白名单和登录/灰度条件；确认下发值确实可控制页面路径或目标文档，而非仅替换 API 域名、图片地址或固定页面的数据 ID。
4. 保存相关调用点与响应/配置快照，核对当前 App 实际消费的值。只抓到一个 URL 不能证明只有一个页面；只搜索不到 `url` 字符串不能证明没有动态入口。外部 Deep Link 的任意地址能力单独记录，不冒充后端/配置下发证据。

### 两个分支使用同一判定

| 结论 | 必须提取的 H5 页面集合 |
|---|---|
| 后端/配置下发地址或路由，经转换/校验后仍能选择页面并流入页面导航 | 对其关联的每个 H5 项目当前资源快照，**枚举全部路由**；有独立 UI 的路由逐项提取，包括尚未在当前菜单出现/当前用户无法自然进入的路由。无法渲染者保留为阻塞/未知缺口，不从覆盖分母排除；别名/无独立 UI 项保留归并依据。分别标记 App 已引用、动态候选和保留路由，不把它们都写成当前生产可达 |
| 已核对相关导航入口和调用链，确认只使用固定页面入口 | 从 App 在**本次范围**实际引用的入口出发，覆盖条件入口、原页面后续导航、协议/帮助等链接以及跳转后的页面，形成**使用闭包**；不额外纳入无关功能的固定入口或同站点其他路由 |
| 来源链未恢复、远端配置未知，或无法排除动态下发 | 标记动态入口/路由范围未知；继续恢复调用链，并对已取得的相关 H5 项目枚举全部已知路由作为待提取候选，说明仍缺哪些资源。不能默认走“仅固定入口”，也不能把已知候选数称为全部路由数 |

“全部”限于本次 App 关联、已确定版本的 H5 项目，不是任意下发域名的整个互联网/后台站点。下发值可选择多个项目时逐个建快照；尚未知的项目/远端页面明确列缺口。域名白名单或路由守卫作为可达条件记录，不删掉“全部路由”策略下尚可渲染的候选。仅域名可配置而页面路径固定、仅数据参数下发时，依据调用链记录为何不属于动态页面选择。

业务分支也执行此范围规则：动态项目的扩展截图进入共用页面目录/补充图册，业务正文与流程图仍只论证请求范围内的实际链路。UED 的页面提取完整性与业务链路完整性分别判断，不能互相替代。

### 枚举路由、补资源并闭合候选

- 保留 App 实际加载的 HTML、入口脚本、运行时路由表、构建/资源清单、懒加载 chunk 与配置快照及哈希。在线 H5 独立更新，不能把不同部署版本的路由与截图混算。
- 从当前实现的路由注册、嵌套路由、自动生成路由/页面模块映射和运行时增补中枚举；没有可读路由表时结合原导航调用、运行时注册与资源恢复，不只正则抓取 path 字符串或请求首页脚本。
- 合并静态、运行与后端/配置线索。对使用闭包，沿每个已确认页面的实际/条件导航继续发现，直到没有未处理目标；对全部路由，逐项处理注册路由和关联懒加载资源，不只截导航菜单。
- 参数路由按模板和可见变体取值；嵌套路由保留真实父布局与上下文。别名、重定向和通配错误路由记录映射/终点，纯跳转且无独立 UI 的项说明理由，不虚造截图。不同文档/无 SPA 的 H5 按已知页面文档和跳转枚举；无法恢复的服务端路由总量记为未知。
- 每个路由落到“有独立 UI、需采集”“别名/重定向等无独立 UI、有依据归并”“阻塞/未知”之一。组件、未注册模块和历史 chunk 作为线索，不自动计为当前路由。不得为了可渲染而删除原守卫/强改业务判断；准备符合原合同的本地状态，打不开就留缺口。

## 4. 选择状态、运行并截图

1. **定范围**：业务分支选业务范围内页面/状态，并纳入上述 H5 扩展集合；UED 全 App 请求纳入所有已发现的原生/RN/Flutter 自有页面/注册页面、独立弹层与有 UI 差异的状态，保留页面单独标识。**H5 在两个分支中始终优先按第 3 节的入口种子和专项策略定范围**：UED“全 App”也不把固定入口项目中未被 App 使用闭包引用的路由纳入截图集合。用户明确要求缩小/禁止动态路由扩展时遵从限制并标明缩小范围，不能再宣称满足默认全路由提取规则。
2. **准备原实现**：先保留未修改原包基线；按 [运行与 Mock](runtime-and-mock.md) 在对应技术层准备会话、数据、参数、配置、Bridge 和依赖。真实输入/交易边界沿用主 skill，不能为凑全图册操作生产金融流程。
3. **逐项打开**：优先自然入口；仅为采集可使用原导航/路由直接定位并标明方式。独立打开失败时补父路由/历史/缓存/配置上下文，不据此判定页面不存在；网页 URL 能加载也不能证明 App 当前可达。
4. **确认与采集**：确认前台宿主、原始资源、页面身份及目标状态已实际渲染，调用 [截图与长图操作](screenshot-workflow.md)。滚动页面/弹层必须完整长图，单屏保留原截图；按状态 ID 关联全部原帧与当前文件对应的最新校验结果，历史 `passed` 不代替本次复核。使用 Manifest 变化的分析副本时，先保留条目比对及语义验收结论。在原 App 中用合规本地数据驱动原组件的截图可通过图片验收，须标记 Mock/直接定位，不能据此证明自然入口或真实后台结果。浏览器/预览替代来源单独分组，不覆盖 App 实拍状态。
5. **补发现**：运行中发现新路由/条件页面，回候选清单并重算范围；页面改版则建新版本快照，不覆盖旧证据。拼接失败保留原帧并说明原因，不能记为已完成页面图片。

## 5. 覆盖与图片验收

在第 9 步[审查工作流](review-workflow.md)中调用本节，对照原代码和实际运行，核对每个候选的纳入/排除依据、各栈恢复范围、动态 H5 判定、路由集合与参数/状态代表性。

统计分别列出候选路由/页面数、需提取的页面状态数、App 内原图完成数、浏览器/预览替代数、阻塞/未知数、无独立 UI 归并数与长图失败数；分组互斥或明确统计维度，不把路由数与截图数混为覆盖率。被排除/归并的项仍保留证据，未知总量不报百分比。

第 9 步先完成覆盖复核，再分别记录以下结论：

| 结论 | 条件与后续 |
|---|---|
| 页面提取完成 | 本次页面/路由集合边界和 H5 策略已核实；所有需采集项都有通过来源与完整性复核的 App 原图；别名/无 UI/排除项有审定理由，没有资源/状态/长图缺口 |
| 页面提取受限 | 动态来源、关联项目、路由/页面总量仍未知，或有未恢复资源、阻塞状态、替代来源、未完成长图；即使已知候选都已采集也只能说明“已知集合采集完成”，不能宣称本次全部提取完成 |
| 退回修正 | 页面范围、来源标签、截图/哈希或覆盖结论存在未修正矛盾，回对应阶段修正并复核后再交付 |

页面提取受限是补证状态，须回第 5–8 步继续处理，不是结束许可。按 [调研闭环与完成条件](completion.md) 达到完成门槛后进入第 10 步；只有真实阻塞或用户明确要求部分结果时，才检查并先提供已核实的图册/图片包；缺口及恢复动作保留在内部和聊天，图册不写“未完成/受限”等状态。浏览器补图可单独交付，但不使尚缺的 App 内实拍自动完成。任何“完成”声明都必须带本次范围；只有全 App 范围审定完成才可称 App 全部界面提取完成。

业务事实复核、页面图片覆盖、最终呈现检查分别记录。某个扩展 H5 页面阻塞不推翻已经证实的业务事实，但图片缺口仍须内部跟踪、在聊天说明，报告仅引用已通过图片，不能把事实复核通过写成截图全部完成；UED 也不以业务流程尚未研究为阻塞。单页图片的来源/长图验收标准不因分支或范围缩小而降低。
