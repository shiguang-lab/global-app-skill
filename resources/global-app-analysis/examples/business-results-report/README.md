# 业务结果报告格式示例

本例提炼自用户指定的 `analysis/借款流程分析.html`：按 App 分组、按业务阶段连续阅读，流程图与对应原始 UI 就近查阅。只复用阅读结构，不沿用示例产品的状态值、条件、流程或供应商结论。

- [可视结构示例](report.html)：可离线打开的 HTML，含已渲染流程图、阶段说明、折叠页面详情和字段表。
- [示例图源码](main-flow.mmd)：用于后续编辑，不展示在业务报告正文。

## 面向读者的内容

报告回答：功能做什么、入口在哪里、何时显示、用户做什么、成功/失败/取消后去哪里。只呈现分析结果、业务规则及原始页面，不要求读者阅读代码来理解结论。

代码、接口、哈希和运行日志用于内部分析及复核。默认不在正文、折叠面板、附录或导航中放“证据”“原始请求”“代码核对”等入口；不要只是用 CSS 隐藏仍被写入报告的材料。用户明确要求技术细节时再单独提供。

## 默认阅读顺序

### 1. 标题与业务总览

- 标题写 App 名称和本次分析主题；仅保留必要日期、App 版本。
- 用一段话直接回答核心问题，再用少量结果卡片概括关键区别。
- 提供可点击的主线阶段导航。
- 多款 App 时提供按 App 选择的阅读入口，必要时折叠展示差异对照。
- 不以取包渠道、反编译方法、设备恢复或验证范围清单开篇。

### 2. 按 App 独立组织完整链路

每款 App 连续讲完本次范围内的流程，避免跨 App 按“所有登录页”“所有资料页”混排。仅分析一个 App 时保留一个产品章节；指定功能仅保留该功能与必要上下游，不为套模板扩展还款、复借等无关环节。

产品章节包含：

1. 一段业务概述。
2. 主线阶段导航。
3. 可展开的完整流程图；复杂场景另有对应阶段子图。
4. 按顺序展开的业务阶段。

流程图用 Mermaid 实际渲染。节点、箭头写业务动作和条件，点击节点可展开对应说明或原始 UI。保留适合宽度/原尺寸阅读；图源码保存在内部分析目录。

### 3. 每阶段先讲业务，再展开页面

```text
阶段编号 · 阶段名称
一句话说明本阶段在链路中的位置。

进入条件：用户处于什么状态，从哪里进入。
用户操作：填写、选择、确认或等待什么。
成功后：转到哪一步，改变什么业务状态。
失败或其他条件：失败、取消、权限拒绝、配置变体如何处理。

[可展开] 本阶段具体分支：标题 + 条件 + 操作 + 后续
[可展开] 本阶段流程图
[可展开] 字段、权限和办理规则
[可展开] 本阶段页面与原始 UI（按页面/状态分组）

下一阶段 / 返回业务总览
```

所有用户状态先翻译成业务含义，例如“授信审核中”“授信通过、未借款”。不要用内部数值、字段名或路由作为主要解释。

入口显示条件要结合用户状态、页面选择及按钮含义解释。首页显示某入口，与独立页面打开方法是否再次校验资格，是不同层次；不能用后者替代 UI 显示分析。

### 4. 原始页面的统一说明

```text
页面编号 · 页面/状态名称
当前状态或进入条件（摘要）

原始完整截图（可展开/查看原尺寸）
如何进入：上一个入口/页面/用户动作。
何时显示：对应状态和必要条件。
界面显示：核心内容、输入和默认选项。
用户操作：按钮、选择、确认、关闭。
操作与后续：成功、失败、取消、重试或续办的去向。

字段/权限表：数据或字段 | 要求 | 交互、条件与校验
返回对应流程图 / 上一步 / 下一步
```

页面编号用于导航原图，不是证据编号。没有截图的状态只讲已知业务，不编造界面、按钮文案，也不用重绘图冒充 App。

截图旁用“原版 App 界面”或“原始 H5 页面 · 演示数据”等简短说明即可。不得把演示金额、身份资料、模拟审批或 SDK 回调当作真实报价、真实审核通过或到账。

### 5. 分支与业务规则

- 关键判断放在发生的阶段旁，不全部挤到末尾。
- 场景对照表可用“场景 | 出现条件 | 用户操作 | 处理与后续 | 对应 UI”。
- 字段表可用“数据/字段 | 必填/可选/条件必填 | 交互、联动与校验”。
- 各种配置是替代路径，不排成所有用户都必经的连续步骤。
- 业务规则不清楚时先回到代码、App 交互与隔离 Mock 补证，按 [调研闭环与完成条件](../../references/completion.md) 关闭问题；最终正文写确定的条件、操作和结果。确认不存在的功能不列；真实阻塞只在内部记录和聊天中说明，报告不出现“待确认/未完成/受限”等状态，也不能因此停止范围内走查。

### 6. 专项内容与收尾

供应商、权限比较等仅在用户要求或本次主题需要时加入：

- 供应商表：业务类别 | 供应商/服务 | 用途与适用范围。
- 仅列已核实的技术服务、资金/征信机构和支付渠道；不加代码路径、SDK 包名、行号或哈希。
- 页面示例来源与已验证的适用条件在相应位置简短说明；末尾无需附内部取证包或环境恢复记录。

## 呈现约定

- 深色标题区、浅色底、白色业务分区；业务总览和 App/阶段导航容易找到。
- 默认显示主线解释、业务结论与关键条件；分支、字段和原图按需展开，避免巨图或密集截图占据整页。
- 点流程图节点或页面链接时，自动展开其所在折叠层并滚动到目标；不是只改 URL 而页面仍折叠。
- 一图对应一处业务位置，避免单独图册与正文脱节；原尺寸查看不改原图。
- 内嵌必要图和图片后检查桌面、手机、断网阅读与锚点；不要依赖外部源码链接才能看懂结果。

## 最小验收

1. 只读正文即可回答本次核心问题。
2. 各 App 的流程独立连续，各阶段都有条件、操作与正常/异常去向。
3. 入口显示条件、流程图和原始 UI 对得上。
4. 图与页面、阶段之间可互相导航，折叠内容能自动展开。
5. 没有代码证据、请求体、文件行号、哈希、内部编号和调研过程。
6. 没把截图示例或局部推断写成真实后台成功。
7. 范围内问题、必要 App 交互与图片均已通过；正文只写具体结论，确认不存在的功能不列；阻塞只在内部/聊天处理，不能以报告可阅读代替调研完成。
